1. Почему число 1 занимает 4 байта, хотя для его записи достаточно одного байта?
потому что строго выделяется 4 байта на int 
2. Что изменяется в байтовом представлении числа 256?

По сравнению с числом 1 (01 00 00 00) единица переехала из младшего байта во второй. Это отражает вклад разряда 2^8 = 256: младший байт может хранить только 0–255, для 256 нужно уже второе место. 

3. Почему число 65536 уже требует другого набора байтов?

Здесь единица стоит в третьем байте. Первых двух байтов (0–65535) уже не хватает — нужно третье место для разряда 2^16. Это та же закономерность: каждый следующий байт добавляет 8 бит, то есть в 256 раз больше значений.

Число: 305419896
В hex: 0x12345678
Little-endian: True
Байты числа: 
78-56-34-12
В памяти байты числа идут именно в таком
порядке, потому что архитектура x86/x64 использует
little-endian («младший — первым»). Это означает, что
младший байт числа хранится по младшему адресу, то есть
первым в массиве байтов. Число 0x12345678 состоит из
четырёх байтов: 12 (старший), 34, 56 и 78 (младший).
При записи в память они располагаются в обратном порядке
относительно привычной записи: 78 56 34 12.

Почему количество символов и количество байтов может отличаться?
Потому что символ — это логическая единица текста (буква, цифра,
знак), а байт — единица хранения данных в памяти. В кодировке
UTF-8 один символ занимает от 1 до 4 байт: латинские буквы и
цифры кодируются одним байтом,
буквы кириллицы — двумя байтами, иероглифы — тремя или четырьмя.
Поэтому строка "ABC" из трёх латинских символов занимает 3 байта, а строка "Привет" из шести кириллических символов
занимает 12 байт (6*2).
