потому что строго выделяется 4 байта на int 
2. Что изменяется в байтовом представлении числа 256?

По сравнению с числом 1 (01 00 00 00) единица переехала из младшего байта во второй. Это отражает вклад разряда 2^8 = 256: младший байт может хранить только 0–255, для 256 нужно уже второе место. 

3. Почему число 65536 уже требует другого набора байтов?

Здесь единица стоит в третьем байте. Первых двух байтов (0–65535) уже не хватает — нужно третье место для разряда 2^16. Это та же закономерность: каждый следующий байт добавляет 8 бит, то есть в 256 раз больше значений.

3–5 предложений о том, как числа и текст представлены в памяти и почему для
интерпретации байтов нужны правила.

Числа и текст хранятся одинаково, поэтому открывая одни и те же кодировки разными правила получаются разные значения. Поэтому необходимо знать правила.

1. Что такое байт и сколько бит содержит один байт?
байт - минимальная единица памяти компьютера, один байт содержит 8 бит, и может принимать 256 значений
2. Почему int занимает несколько байтов?
Тип int в C# занимает 4 байта (32 бита),
что позволяет хранить значения от −2 147 483 648 до
2 147 483 647. Размер фиксирован — компилятор и процессор
знают, сколько памяти выделять под каждую переменную типа
int, и не подстраивают размер под конкретное значение.
Если бы размер был переменным, усложнилась бы работа
процессора и передача данных между программами.
3. Что показывает BitConverter.GetBytes()?
Метод возвращает массив байтов byte[], в котором
переданное значение хранится в памяти текущей машины.
4. Что означает BitConverter.IsLittleEndian?
Это логическое свойство, которое показывает порядок байтов
на текущей машине. True означает little-endian — младший
байт числа хранится по младшему адресу, то есть первым в
массиве байтов. False — big-endian, когда первым идёт
старший байт.
5. Почему порядок байтов может отличаться от привычной записи числа?
Привычная запись числа — big-endian: старший байт слева,
младший справа. Так число удобно читать человеку. Но
процессорам x86/x64 удобнее little-endian — младший байт
первым, потому что с него начинаются арифметические операции.
Поэтому число 0x12345678 в памяти выглядит как 78 56 34 12.
Само число при этом не меняется — меняется лишь порядок
хранения его отдельных байтов.
6. Почему количество символов строки не всегда равно количеству байтов?
Потому что символ — это логическая единица текста (буква,
цифра, знак), а байт — единица хранения данных в памяти.
7. Что делает Encoding.UTF8.GetBytes()?
Преобразует строку string в массив байтов byte[],
закодированных в UTF-8. Каждый символ заменяется на
1–4 байта согласно его коду Unicode. Это прямой процесс
кодирования: текст → байты. Например, `"Hello"` → `48-65-6C-6C-6F`,
а `"Привет"` → `D0-9F-D1-80-D0-B8-D0-B2-D0-B5-D1-82`.
8. Зачем для обратного преобразования текста используется `Encoding.UTF8.GetString()`?
Чтобы из массива байтов восстановить исходную строку.
Байты сами по себе не содержат информации о том, в какой
кодировке они были записаны, — одну и ту же последовательность
можно прочитать как UTF-8, Windows-1251, KOI8-R и получить
разный текст.
9. Почему одни и те же байты могут интерпретироваться по-разному?
Потому что байты — это просто числа, и сами по себе они
не имеют «врождённого» смысла. Смысл появляется только
тогда, когда программа знает, по каким правилам их
читать
10. Чем представление числа в памяти отличается от представления текста?
Число int хранится как фиксированные 4 байта в порядке
little-endian, и его значение однозначно: чтобы восстановить
число, достаточно знать тип BitConverter.ToInt32, никакая
кодировка не нужна. Текст же хранится как последовательность
байтов переменной длины**, и чтобы её прочитать, нужна
кодировка (UTF-8, UTF-16, Windows-1251).
